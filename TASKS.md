# План разработки WTIS (Task Roadmap)

Этот документ служит единственным источником истины для планирования и отслеживания задач развития проекта WTIS.

## Как пользоваться этим документом

1. **Статусы задач**:
   - `[ ]` — Задача не начата.
   - `[*]` — В работе (активная фаза).
   - `[x]` — Завершено (принято в main ветку).
   - `[~]` — На проверке (Code Review / Тестирование).

2. **Приоритеты**:
   - 🔴 **Critical**: Блокирует работу, критические баги, безопасность.
   - 🟠 **High**: Важный функционал для ближайшего релиза.
   - 🟡 **Medium**: Улучшения, оптимизация, технический долг.
   - 🟢 **Low**: "Хотелки", косметические правки, будущие фичи.

3. **Формат задачи**:
   ```markdown
   - [ ] **[ID-Номер] Название задачи** (Приоритет)
     - **Контекст**: Зачем это нужно?
     - **Задача**: Что конкретно сделать?
     - **Критерии готовности (DoD)**: Как поймем, что готово?
     - **Технические заметки**: Подсказки по реализации.
   ```

## ЭТАП 1: Стабильность и Производительность (Q1 2024)
*Цель: Устранить узкие места в производительности и подготовить базу для масштабирования.*

### 🟠 High Priority

- [ ] **[PERF-01] Внедрение Web Workers для тяжелых вычислений** (High)
  - **Контекст**: При обработке матриц >1000x1000 интерфейс зависает.
  - **Задача**: Вынести алгоритмы аппроксимации и фильтрации (Собель, медианный) в отдельные потоки Web Workers.
  - **Критерии готовности (DoD)**:
    - UI остается отзывчивым (FPS > 30) во время расчетов.
    - Реализована передача данных через `Transferable objects` (ArrayBuffer) для скорости.
    - Покрыто тестами: корректность результатов совпадает с синхронной версией.
  - **Технические заметки**: Создать пул воркеров в `src/workers/`. Не создавать новый воркер на каждый чих.

- [ ] **[MEM-02] Оптимизация потребления памяти при работе с историей** (High)
  - **Контекст**: При 50 шагах истории браузер потребляет >1GB RAM.
  - **Задача**: Реализовать адаптивную глубину истории и сжатие состояний.
  - **Критерии готовности (DoD)**:
    - Потребление памяти при 50 шагах не превышает 300MB.
    - Реализован механизм сброса старых состояний при достижении лимита.
  - **Технические заметки**: Использовать дельта-кодирование (хранить только изменения) или даунсемплинг для превью в истории.

- [ ] **[TEST-03] Настройка инфраструктуры тестирования** (High)
  - **Контекст**: Отсутствие автотестов приводит к регрессиям.
  - **Задача**: Подключить Jest для JS и Pytest для Python. Написать первые 10 тестов на критическую логику.
  - **Критерии готовности (DoD)**:
    - CI пайплайн запускает тесты при каждом пуше.
    - Покрытие ключевых модулей (`matrix`, `imageOps`) > 60%.
  - **Технические заметки**: Конфигурация в `jest.config.js` и `pytest.ini`.

### 🟡 Medium Priority

- [ ] **[CACHE-04] Реализация кэширования результатов фильтров** (Medium)
  - **Контекст**: Повторное применение того же фильтра пересчитывается заново.
  - **Задача**: Внедрить LRU-кэш для результатов операций.
  - **Критерии готовности**: При повторном запросе с теми же параметрами результат возвращается мгновенно из кэша.

## ЭТАП 2: Функциональное расширение (Q2 2024)
*Цель: Расширить инструментарий пользователя и улучшить Workflow Editor.*

### 🟠 High Priority

- [ ] **[FEAT-05] Добавление частотных фильтров (FFT)** (High)
  - **Контекст**: Пользователям нужен анализ частотного спектра для удаления шумов.
  - **Задача**: Интегрировать библиотеку для FFT (например, `fft.js`) и создать UI для частотной маски.
  - **Критерии готовности**:
    - Возможность просмотра спектрограммы.
    - Применение низкочастотных/высокочастотных фильтров.
  - **Технические заметки**: Требует careful handling комплексных чисел в JS.

- [ ] **[WF-06] Параллельное выполнение узлов в Workflow Editor** (High)
  - **Контекст**: Графы выполняются строго последовательно, хотя некоторые ветки независимы.
  - **Задача**: Реализовать планировщик, выявляющий независимые ветки графа.
  - **Критерии готовности**: Время выполнения разветвленных графов сократилось на 30%+.

### 🟢 Low Priority

- [ ] **[UI-07] Темная тема интерфейса** (Low)
  - **Контекст**: Длительная работа в ярком интерфейсе утомляет глаза.
  - **Задача**: Добавить переключатель темы и CSS переменные для цветов.
  - **Критерии готовности**: Все экраны корректно отображаются в темной теме, выбор сохраняется в LocalStorage.

## ЭТАП 3: Архитектура и Инфраструктура (Q3 2024)
*Цель: Подготовка к промышленной эксплуатации и контейнеризация.*

### 🔴 Critical

- [ ] **[ARCH-08] Рефакторинг бэкенда на модульную структуру** (Critical)
  - **Контекст**: `app.py` разросся до 1000+ строк, сложно поддерживать.
  - **Задача**: Разделить роуты, модели и логику MinIO на отдельные пакеты.
  - **Критерии готовности**:
    - `app.py` содержит только инициализацию и регистрацию блюпринтов.
    - Логика разделена по папкам `routes/`, `services/`, `models/`.
  - **Технические заметки**: Использовать Flask Blueprints.

### 🟠 High Priority

- [ ] **[DEVOPS-09] Dockerization проекта** (High)
  - **Контекст**: Сложность развертывания на новых машинах.
  - **Задача**: Создать `Dockerfile` для приложения и `docker-compose.yml` для связки App + MinIO.
  - **Критерии готовности**: Развертывание системы одной командой `docker-compose up`.
